C Game Development Course Project

Twixt Game Building Using C

A C implementation of the strategy board game Twixt, built as part of my first-semester Computer Programming course project.

What it does

This project recreates Twixt as a playable game in C. It manages the board state, enforces move and link rules, and checks the core win condition of forming a connected path across the board.

Why I built it

I built it for my Computer Programming course in my first semester of college. I wanted something that would push my logic and problem-solving skills while still being interesting enough to show to other people.

What I'd do differently

If I revisit it, I would separate the game logic from the interface more cleanly and spend more time testing edge cases. At that stage, I was mainly focused on getting the full game working end to end.

Technology tradeoffs

Using C gave me fine-grained control over the implementation, which made it a strong learning experience. The tradeoff was that even small changes took more effort than they would have in a higher-level language.

ESP32 RFID IoT

Smart Attendance System Using ESP32

An automated classroom attendance system that uses RFID scanning, embedded hardware, and server uploads to reduce manual work.

What it does

The system is designed for a classroom entry point. Students scan RFID cards, the hardware confirms the event through sensors, shows a message on an OLED display, logs the attendance, and uploads the record to a server.

Why I built it

Manual attendance takes time and still leaves room for mistakes. This project was meant to make that process faster, more reliable, and easier to handle in a real classroom setting.

What I'd do differently

If I continue working on it, I would focus more on duplicate-scan handling, network failure cases, and better teacher-side visibility into the stored records. Reliability matters a lot more once hardware is involved.

Technology tradeoffs

The ESP32 is a strong fit because it gives you embedded control and connectivity in one board. The tradeoff is that integrating sensors, communication, and physical usage makes reliability and testing more important than in a purely software-only project.

Core components: RFID reader, IR sensor, ESP32, OLED display, and a server-backed attendance log.

Hackathon Web App AI Detection

AI Detector

A hackathon web application that checks whether submitted text, audio, or video content appears to be AI-generated.

What it does

The app supports three kinds of input. Users can paste text directly, upload audio for transcription and analysis, or upload video so the spoken content can be processed and checked through the same workflow.

Why I built it

We built it as part of a hackathon because the problem felt current and interesting, and it gave us a chance to work on something multimodal instead of staying inside a single narrow feature.

What I'd do differently

With more time, I would improve how the app explains its predictions instead of only returning a result. For tools like this, users usually care just as much about the reasoning as the final label.

Technology tradeoffs

Supporting text, audio, and video in one application makes the tool much more useful, but it also increases complexity quickly. The final output depends heavily on preprocessing quality, especially when transcription is involved.
